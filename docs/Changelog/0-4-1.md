# Changelog — 0.4.1

## BehaviorTree — Bug fixes

Found by a five-round adversarial review of the 0.4.0 tree (each round a validator proving a defect with a repro, then a fix, then re-validation). No API removed; every existing test and the differential harness against the 0.3 tree still pass.

### Agents driven by `TickAgent`

- **Two or more agents on one tree driven by `TickAgent` misfired every tick-stamped node.** The tree's tick counter and the detached-child sweep were global and advanced per `TickAgent` call, so with agents A and B ticked in turn, `MemorySequence` reset its cursor every frame, `WaitGate` never fired, `OneShot(reset)` / `WasFieldUpdated` saw a visit gap every frame, and `FireAndForget` / `Scope` children were halted and restarted every frame. This is the FSM / GOAP connector pattern. Each `TickAgent`-driven agent now has its own tick counter and its own detached-child buffer; `Tick()` is unchanged.
- **Documented: one driver per agent, for life.** An agent is driven by `Tick()` or by `TickAgent()`, never both (a switch reads as a visit gap to stamp-comparing nodes and orphans a running `MemorySequence` child). On a `Tick()`-driven tree, `TickAgent` must not be called from callbacks either, even for another agent. `Halt(slot)` first if an agent must change drivers. See "Tick or TickAgent, not both" in [behavior-tree.md](../behavior-tree.md).

### Removal and halt re-entrancy

- **`RemoveAgent` / `Halt` of the same agent from its own `OnHalt` crashed the cascade** ("attempt to perform arithmetic (add) on nil") or recursed until stack overflow with a bare leaf root, leaving the agent half-removed. A nested halt of the agent being halted is now a no-op; a removal requested from any halt-time or removal-time callback is queued and applied when the current cascade completes, inside the same top-level call.
- **A removal queued twice could destroy a different agent.** When agent A was removed, then re-spawned into the same slot from another agent's `OnAgentRemoved` in the same flush, a duplicate queue entry tore the new agent down. Queued removals are now deduplicated per slot until the teardown completes.
- **`Tick` / `TickAgent` from a removal or halt callback re-entered the removal queue** mid-teardown (double teardown, phantom agents, stuck bookkeeping). `Tick()` now throws from such callbacks; `TickAgent` of the agent being removed throws; `TickAgent` of another agent is allowed on a `TickAgent`-driven tree and defers its flush to the outer call.
- **`GetStatus` was stale after `Halt` / `RemoveAgent` for agents whose last status was not RUNNING**, and in external-id mode one status entry leaked per removed id. Cleared unconditionally again.

### Hooks that throw

- **One throwing hook no longer disables the tree.** Previously an error from any hook (tick-time or halt-time) unwound past the tree's bookkeeping; every later `RemoveAgent` was queued and never processed (unbounded growth), and a `TickAgent`-driven tree threw "cannot be called during Tick" forever. Hooks now run under `pcall` at the tree boundary: the first error is rethrown by the outermost tree call after the frame, halt or removal has completed, so the tree is consistent afterwards. Steady-state allocation stays at 0 B per tick; `TickAgent` pays one `pcall` per call (about +40 ns natively), `Tick()` one per frame.
- **A throwing `OnHalt` no longer aborts the rest of the cascade.** `Parallel` siblings are still halted, a leaf's `OnExit` and `OnLeave` still follow its `OnHalt`, `Scoped` still leaves its span, and `Cooldown(reset_on_halt)` still resets. Under `Halt()` the skipped nodes previously kept their per-agent state, so `OnStart` / `OnEnter` were skipped on the restart.
- New public `tree.HaltChild(halt, slot)` for custom nodes that halt more than one child or run a hook after halting one; the built-in nodes use it. See "When a hook throws" and custom-node rule 3 in the docs.

### Documented constraint

- **A built node belongs to one tree.** Per-agent state is keyed by slot alone, so two allocating trees sharing a node would both write slot 1 into it and `RemoveAgent` on one would clear the other's agent. Build a second copy for a second tree; two external-id trees with disjoint ids are the one safe case. The 0.3 → 0.4 migration table said nodes were shareable across trees; corrected.

## Measurements (Roblox Studio, current build)

`Scope` / `FireAndForget` / `RunningGate` / `Scoped` are the only nodes that use the detached-child list; the cost is per visit of such a node, not per tree. Micro tree `Sequence(X, Plug, Plug, Leaf)`, 1000 agents, ns per agent-tick: a plain node visit +11 native / +52 interpreted; a `Scope` visit +93 / +191; `FireAndForget(Wait)` +80 / +156. On the npc scenario with a Scope at the head of every taken branch (0.27 visits per agent-tick): 0.165 → 0.212 µs native, 0.312 → 0.340 µs interpreted. Place a `Scope` after the branch's condition, not before it, so it is paid only when the branch is taken.
