# Changelog — 0.4.2

## BehaviorTree — Bug fixes

Found by a two-round validator/worker review of the 0.4.1 tree (each round a worker fixing test-first, then validators trying to break the fixes and hunting for new bugs with probes). Every new regression test failed before its fix. No API removed or changed; the steady-state per-tick cost is unchanged.

### Parallel

- **`Parallel(ALL, ALL)` never finished when its children ended with a mix of successes and failures.** Every child was done, but neither "all succeeded" nor "all failed" held, so it returned `RUNNING` forever. Now, once every child has finished without meeting the success policy, it returns `FAILURE`. The same path fixes `ONE`/`ONE` with no children, which was also stuck. With no children: `ALL`/`ALL` and `ALL`/`ONE` return `SUCCESS`, `ONE`/`ALL` and `ONE`/`ONE` return `FAILURE`.

### Re-entrant tree calls

- **`Tick()` called during a tick re-entered the walk** (from an `OnTick` hook, during `Tick()` or during `TickAgent()`): it advanced `TickCount` and ran the end-of-frame sweep in the middle of the frame. It now throws `"BTree: Tick cannot be called during Tick"`, like `Halt`, `HaltAll` and `TickAgent` already did.
- **`TickAgent(A)` from a hook of A's own halt, or of the end-of-frame sweep of A's detached children, corrupted A's state.** The nested frame restarted nodes the halt was still tearing down (`GetStatus` stayed `RUNNING`, and the next `Halt` failed with an internal error), or the outer sweep halted a `FireAndForget` child the nested frame had just visited. It now throws `"BTree: agent N is being halted"`. `TickAgent` of **another** agent from those callbacks is still allowed on a `TickAgent`-driven tree.

### Hooks that throw

- **An `OnHalt` that threw during a halt caused by a node's own tick left the agent stuck.** This covers `ReactiveSequence` / `ReactiveFallback` switching or finishing, `WhileDoElse` switching branch, and `Timeout` running out. The node kept the old child recorded as running, so it was halted a second time later (a second `OnHalt`, or an internal error on every later tick when that child was a composite). Reactive composites also never recorded the child that had just started, so it was never halted, not even by `RemoveAgent`. These halts now go through `tree.HaltChild`: the halt completes, the tick carries on, and the error is rethrown after the frame. The `pcall` only runs when a child is actually halted, so steady-state ticks cost the same.
- **Behavior change:** such an `OnHalt` error no longer ends that agent's frame. The agent gets its status for the frame, and the error is still rethrown by the outermost tree call.
- The `Gate` example in [custom-nodes.md](../custom-nodes.md) had the same problem and now halts through `HaltChild`. Custom-node rule 3: halt through `tree.HaltChild` whenever your `Tick` halts a child.

### Documented, not changed

- **After an error from a tick-time hook** (`OnTick`, `OnStart`, `OnEnter`, …) the tree can lose track of what the agent has running: a node started in that frame may never be halted, not even by `RemoveAgent`, and a later `Halt` or `RemoveAgent` may reach a node that finished in that frame. A fix would cost a `pcall` per node tick. See "When a hook throws" in [behavior-tree.md](../behavior-tree.md#when-a-hook-throws).
- **`GetAgents()` returns the tree's own list**, and `RemoveAgent` reorders it, so removing agents while looping over it skips about half of them. Loop over a copy: `for (const slot of [...tree.GetAgents()]) tree.RemoveAgent(slot)`.

## Docs

Rewritten for readability. [behavior-tree.md](../behavior-tree.md) now starts with how a behavior tree works and a first tree walked through frame by frame, then covers reactive composites, core concepts, a "which node do I need?" table, the node reference, and rules and edge cases. The README has a "Which one do I need?" table and a quick start. The BTCreator, FSM, GOAP and Blackboard guides are restructured. Every TypeScript example typechecks against the source.

Corrected against the source:

- **BTCreator:** the `Plug` parameter is `status`, not `Status`. `RetryUntilSuccess` / `RetryUntilFailure` exist only in `1.0.0` files; `2.0.0` files use `KeepRunningUntilSuccess` / `KeepRunningUntilFailure`. `EntryPoint` is a marker whose single child becomes the root. Parameters are required unless marked optional.
- **FSM:** a higher priority number is checked first, and a state's own transitions always beat any-state transitions. A tree driven through `BehaviorTreeConnector` must not also be ticked with `tree.Tick()`.
- **BehaviorTree:** a `Scope` at the head of a plain `Sequence` fires `OnExit` on the next frame while its branch is still active; the docs now recommend `Scoped`. `FireAndForget` has the same constraint.
- **GOAP:** an action's effects are applied to the world state when it succeeds. Replanning (every second by default) halts the running action, so an action that takes longer than the planning interval never finishes; raise it with `SetPlanningInterval`. `Effect.Insert` / `Effect.Remove` change the real world state's array while the planner only simulates an action.
